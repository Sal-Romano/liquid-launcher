# Design: Pane (ships as dev.sal.glass, the existing scaffold)

Produced 2026-11-01 by the engineer-first designer; adopted as the build spec.

## concept

Pane is a photo frame first and a launcher second. The 4K photo fills the whole 960x540 dp screen; a 152 sp glass-numeral clock floats horizontally centred at 43% height; one row of up to eight 84 dp glass squircle tiles hangs 36 dp above the bottom edge. Nothing else is drawn: no row background, no dark scrim by default, no labels except a small glass pill above the one focused tile. After 10 s without a key press the row fades out completely (clock stays), so the idle screen is photo + time; any key brings the row back in 220 ms with the last-focused tile lifted. Glass is faked with one pre-blurred 480x270 copy of the wallpaper sampled in screen space under every shape (plus tint, rim and shadow passes), so there is zero runtime blur; and every tile, row and action is data in one JSON config, so a Home Assistant toggle or a "launch Moonlight" shortcut is a new tile type, not a new screen.

## layout

All numbers in dp on a 960x540 dp canvas (1920x1080 px, density 320). Safe insets: 48 left/right, 32 top, 36 bottom (5% overscan guard).
Z-order bottom to top: wallpaper(current) -> wallpaper(next, fading in) -> optional legibility scrim -> clock block -> dock -> label/context pill -> overlays (All apps / Settings) -> toast.
- Wallpaper: full bleed 0,0 to 960x540, ContentScale.Crop, in its own graphicsLayer for Ken Burns.
- Clock block, centred on x=480: date text baseline y=158 (22 sp, ~200 wide); digits line box y 156-308 (152 sp, lineHeight 1.0), glyph caps y 178-288 (cap height 110), block centre y=232 = 43% of height; "10:42" is 390-410 wide (x 280-680, 41% of width). 24-hour "23:59" has the same width thanks to tabular figures.
- Dock: tile centres y=462; tiles 84x84 (y 420-504); 16 gap; LazyRow with contentPadding 48; when content fits (<= 8 tiles = 784 wide) it is centred (x 88-872), otherwise it scrolls keeping the focused tile >= 1 tile from either gutter. Default content: 5 pinned apps + All apps tile = 6 tiles = 584 wide (x 188-772). Focused tile scales 1.10 (92.4, visually y 416-508). Icon inside: 56x56 centred.
- Focused label pill: height 28, bottom edge y=404 (376-404), horizontal padding 14, min width 72, centred over the focused tile; replaced by the context popover when open.
- Context popover (long OK): 220 wide, rows 40 tall, bottom y=404, anchored over the tile, clamped to the 48 gutters.
- Toast pill: top centre y 32-68 (36 tall), max width 480.
- Wallpaper info card (long Menu): bottom-left, x 48, bottom y 404, 300x88.
- Settings sheet: right-anchored, x 548-928 (380 wide), y 32-508, corner 28; section headers 36 tall, rows 48 tall, 20 side padding; value column right-aligned.
- All apps sheet: full screen with black 0.45 scrim; title "All apps" 28 sp at (48,44); grid 7 columns of 84 tiles, 20 gaps = 708 wide centred (x 126-834); first tile row y 96; row pitch 132 (84 tile + 8 + 20 label + 20 gap); 3 rows visible then vertical scroll; sections "TV apps", "Other apps" (opt-in), "Hidden" (opt-in, drawn at alpha 0.45).
- Legibility scrim (setting Auto, default): vertical gradient only over y 400-540, black 0 -> black a, a = clamp(dockZoneLuma - 0.45, 0, 0.25). On most dark landscapes a = 0 (no scrim at all).
- Footprint while active: 6 tiles = 42,336 dp^2 = 8.2% of the screen, 8 tiles = 10.9%, all of it translucent; idle: 0%.

## clock

Typography: bundled OFL Inter 4 static files in res/font: InterDisplay-Medium.ttf for the digits (display optical size, tighter at large sizes), Inter-Medium.ttf and Inter-SemiBold.ttf for UI. Digits: 152 sp, weight 500, letterSpacing -0.02 em, lineHeight 152 sp, fontFeatureSettings "tnum" (tabular figures; no reflow when 1 -> 2). 12/24 h follows DateFormat.is24HourFormat(context) unless overridden in Settings (Follow system / 12 / 24). No seconds, no blinking colon, leading zero off in 12 h ("9:41"). Sizes S/M/L = 120/152/184 sp in Settings.
Position: x centred; block centre y=232 (43%). Why: (1) the optical centre sits ~5% above geometric centre, so 43% reads as "the middle"; (2) the free band above the dock is y 32-404, whose centre is 218, so the block is balanced between dock and top edge; (3) landscape horizons usually sit on the lower third line (y=360): the digits' cap bottom at y=288 clears it by 72, so the time floats in sky/mountain rather than cutting the horizon. Settings offers 43% / 50% in case Sal wants dead centre.
No panel: a plate behind the clock would hide the photo's centre, so the numerals themselves are the glass. Each digit string is drawn as 5 stacked BasicText passes with identical layout (same font/size/tnum, so they register exactly), top pass last: (a) shadow: black 0.40, offset (0, 3), Shadow blurRadius 20 (or, if gfxinfo shows cost, two unblurred copies black 0.25 at +2 and black 0.12 at +6); (b) backdrop: TextStyle(brush = ShaderBrush(ImageShader(blurThumb))) with local matrix = scale(4) translate(-rootX,-rootY) so the blurred wallpaper appears through the glyphs at screen alignment, colorFilter saturation 1.35; (c) frost: light variant white 0.60 when clockZoneLuma < 0.50, dark variant black 0.28 when > 0.60, lerp between; (d) top specular: linearGradient white 0.30 at glyph top -> 0 at 22% of glyph height; (e) rim: drawStyle = Stroke(1.5 dp), brush verticalGradient white 0.90 (top) / 0.35 (50%) / 0.60 (bottom). Result reads as ~75% white glass digits with a bright edge and a soft dark halo, legible over bright sky and night city alike. Settings: Clock style Glass / Solid (Solid = white 0.95 + shadow pass only).
Date: "Sunday, November 1" (DateFormat.getBestDateTimePattern(locale, "EEEEMMMMd")), Inter-Medium 22 sp, white 0.88, letterSpacing 0.02 em, shadow black 0.35 offset (0,1) blur 6, baseline y=158, above the digits like iOS. Toggle Show date.
Animation: the clock sits in one graphicsLayer with CompositingStrategy.Offscreen so its 5 text passes are rasterised once per change, not per frame. Each glyph is its own AnimatedContent keyed on the character: outgoing fades 0 -> 1 alpha over 260 ms and slides +6 dp down, incoming fades in and slides from -6 dp, easing FastOutSlowIn; tabular widths keep siblings still. Tick: coroutine delay to the next minute boundary plus ACTION_TIME_TICK / TIME_CHANGED / TIMEZONE_CHANGED receiver. During a wallpaper crossfade the backdrop pass blends thumb A -> thumb B with the same 1800 ms progress, and the frost variant lerps with it.

## appRow

Tiles: 84x84 dp glass squircles (corner 20 dp, smoothing 0.6 via androidx.graphics:graphics-shapes), 16 dp apart, one LazyRow (focusGroup + focusRestorer, Modifier.animateItem for reorder), centred when <= 8 tiles, scrolling beyond. Each tile shows the app's square launcher icon, not its Leanback banner: icons come from getResourcesForApplication(ai).getDrawableForDensity(ai.icon, DENSITY_XXHIGH=480) (144 px assets), rasterised once to 112x112 px (56 dp), AdaptiveIconDrawable composited then masked by the same squircle at 14 dp radius, cached in memory per component; fallback when no icon > 96 px: monogram (first letter, Inter-SemiBold 28 sp, white 0.9) on accent-tinted glass. Banners are kept in the model for a future "cards" row style but unused in v1 so the row stays one quiet shape. No labels at rest.
Focus: the lifted tile is the focus indicator; no ring. On focus gain: scale 1.00 -> 1.10 with spring(dampingRatio 0.78, stiffness 420) (~280 ms settle); shadowElevation 10 -> 26 dp tween 180 ms FastOutSlowIn; rim alpha x1.2 and its top colour mixed 30% with the wallpaper accent; tint +0.06; a 45-degree sheen band (40% of tile width, white 0 -> 0.25 -> 0) sweeps from -60% to +160% once over 650 ms, CubicBezier(0.3,0,0.1,1). Label pill (28 dp, Inter-Medium 18 sp white 0.92) fades in 120 ms and rises 6 dp 12 dp above the tile. Focus loss: scale back with the same spring, elevation 180 ms, label fades 100 ms. End of row: 6 dp bump, 120 ms, no wrap. OK press: scale to 1.03 in 90 ms + white 0.18 flash 120 ms, then startActivity; row stays as is so it is already there on return.
Staying out of the photo: no row background or shelf; every tile shows a blurred version of exactly what is behind it (screen-space sample), so the photo continues through the glass; 6 default tiles cover 8.2% of the screen; labels only on focus; no global scrim unless the dock zone is bright (Auto scrim above); the row lives in the bottom 15% where landscape foregrounds carry the least detail; and the dock itself (ActionTile "All apps" as the last slot) is the only chrome.
Idle fade: after 10 s with no key (Settings: 5/10/20/60 s/Never) the dock and label animate alpha 1 -> 0, scale 1 -> 0.96, translationY 0 -> +8 dp over 600 ms with CubicBezier(0.4,0,1,1); the clock does not move. The nodes stay composed (alpha only) so Compose focus never dies. Any key wakes it in 220 ms (CubicBezier(0,0,0.2,1)) and that key is consumed, except Menu/Play/Rewind/FF which act immediately. Back while the row is visible hides it instantly (same 600 ms curve) for "show me the photo". Home press (onNewIntent) shows the row and focuses the default tile.
Content rules: dock order from config; entries whose component is not installed (Plex today) are skipped but keep their slot, so Plex appears in slot 1 the moment it is installed (PackageChangeReceiver on ACTION_PACKAGE_ADDED/REMOVED/CHANGED); default hidden packages: com.mediatek.opapp, io.github.toolicious.homeonfire, me.efesser.flauncher, com.spocky.projengmenu, dev.sal.projectivy.localwallpapers, dev.sal.glass. Default dock: Plex (com.plexapp.android), Netflix, Prime Video, Luna, Amazon Music, All apps.

## glassRecipe

One Modifier.glass(shape, variant, focused) draw node used by every panel (tiles, pills, sheets, popovers), reading LocalGlassBackdrop(current thumb, next thumb, crossfade progress, zone luma, accent). No Canvas.clipPath anywhere: every layer is a drawPath fill on a convex path, which Skia tessellates cheaply.
Backdrop source: per wallpaper, a 480x270 software ARGB_8888 bitmap (518 KB) decoded by ImageDecoder.setTargetSize, box-blurred 3 passes radius 5 in Kotlin IntArray (~1 ms on an A73; sigma ~5.5 px at 1/4 scale = ~22 px at 1080p), cached to cacheDir as JPEG so it is computed once per photo. Panels sample it with ImageShader(thumb, Clamp, Clamp) and a local matrix: scale(4) then translate(-panelRootX, -panelRootY) then scale(1.04) about the panel centre (lens magnification); FilterQuality bilinear, so the 4x upsample of an already-blurred image shows no blocks. Positions come from onGloballyPositioned; focus scale is applied by graphicsLayer, which magnifies the sample further for free.
Shape: RoundedPolygon.rectangle(w, h, rounding = CornerRounding(20.dp, smoothing = 0.6f)).toPath() for 84 dp tiles (continuous corners like iOS icons), 28 dp / 0.6 for sheets, capsule (RoundedCornerShape(50%)) for pills. Stroke paths are inset 0.75 dp so the rim stays inside the silhouette.
Layers, bottom to top, light variant (zone luma < 0.50; dark variant in brackets, used when luma > 0.60; lerp in between, variant computed per wallpaper and blended with the crossfade so it never flickers):
L0 shadow: graphicsLayer(shape = glassPath, clip = false, shadowElevation = 10 dp idle / 26 dp focused, ambientShadowColor black, spotShadowColor black); theme sets android:ambientShadowAlpha 0.12 and android:spotShadowAlpha 0.40 (defaults 0.039/0.19 are invisible on photos). Hardware shadow, outline path is convex so Outline.setPath (API 30) casts it.
L1 backdrop: drawPath(path, ShaderBrush(thumb A)); during a crossfade drawPath again with thumb B at alpha = progress; colorFilter = ColorMatrix saturation 1.35 (Liquid Glass's colour vibrance; also the wallpaper colour bleed, since the panel literally shows the photo behind it).
L2 tint (frost): verticalGradient white 0.26 top -> 0.10 bottom [black 0.22 -> 0.34]. Focused: +0.06 on both stops.
L3 inner top highlight: verticalGradient white 0.22 at 0 dp -> 0 at 16 dp [white 0.18 -> 0], the "thickness" lip.
L4 inner bottom glow: verticalGradient white 0.10 over the bottom 10 dp [0.08] (refraction light at the lower edge).
L5 specular rim: Stroke 1.5 dp, verticalGradient white 0.85 (top) / 0.20 (50%) / 0.50 (bottom) [0.95 / 0.35 / 0.65]; focused: alphas x1.2 capped at 1.0, top stop mixed 30% with the wallpaper accent.
L6 outer hairline: Stroke 1 dp on the path grown by 0.5 dp, black 0.15 [0.25], grounds the panel on bright areas.
L7 focus sheen: linearGradient band 40% wide, white 0 / 0.25 / 0, animated from -60% to +160% of the width over 650 ms, drawn as a path fill (no clip).
Accent: mean colour of the thumb's bottom 22% (dock band), HSL saturation x1.4, lightness clamped 0.55-0.72; used in the focused rim and for v2 toggle "on" states (fill accent 0.35).
Text on glass: white 0.92, shadow black 0.35 offset (0,1) blur 4. Sheets use the same recipe plus a flat black 0.18 [0.30] added to the tint so 18 sp settings text passes contrast on any photo.
Cost: per panel 6-8 draw calls, two of them textured; 9 panels on the home screen = ~70 draws plus 9 hardware shadows, well under 2 ms on Mali-G52 at 1080p. Zero runtime blur, zero offscreen layers except the clock.

## wallpaper

Source: MediaStore.Images query with RELATIVE_PATH = 'Pictures/Wallpapers/' (projection _ID, DISPLAY_NAME, DATE_MODIFIED; the TV reports no WIDTH/HEIGHT for pushed files, so dimensions come from ImageDecoder's OnHeaderDecoded info.size). Refresh triggers: ContentObserver on the Images URI, every onStart/onNewIntent (Home press), and every rotation tick; fallback for scan lag after adb push: list /sdcard/Pictures/Wallpapers directly (scoped storage permits reading other apps' media files by path with READ_EXTERNAL_STORAGE) and MediaScannerConnection.scanFile the ones MediaStore does not know yet; Settings has "Rescan folder". Queue: Fisher-Yates shuffle per cycle, never repeating the last shown photo across the boundary; newly found files are inserted at the front of the queue (push a photo, press Home, it appears). Setting Order: Shuffle / By name.
Decode (Dispatchers.IO): ImageDecoder.createSource(contentResolver, uri) -> decodeBitmap with OnHeaderDecoded: setTargetSize to cover 1920x1080 keeping aspect (16:9 source = exactly 1920x1080, a sample-2 decode of the 4K JPEG, 120-250 ms on the A73), allocator ALLOCATOR_HARDWARE (8.3 MB in GPU memory, 0 bytes on the 192 MB Java heap, no texture upload hitch at first draw), setMemorySizePolicy default. Second decode of the same source at setTargetSize(480,270), ALLOCATOR_SOFTWARE, for the blur thumb and zone luma (clock zone y 29-57%, dock zone y 78-100%) and accent colour; thumb cached to cacheDir/thumbs/<id>-<dateModified>.jpg. Display colour: ImageDecoder converts embedded P3/AdobeRGB profiles to sRGB.
Rotation: interval setting 1/2/5/10/30/60 min/Off, default 5 min; prefetch of the next photo starts at T-8 s so the swap never waits on decode. Crossfade 1800 ms: the old hardware bitmap stays at alpha 1 underneath, the new one fades in on top (no mid-fade brightness dip), easing CubicBezier(0.4,0,0.2,1); the glass backdrop thumbs blend with the same progress; the new bitmap is drawn once at alpha 0.004 one frame earlier to warm the texture binding; the old bitmap is recycle()d 1 frame after the fade ends. Manual Rewind/FF = previous/next with the same crossfade and a reset interval timer; Play/Pause freezes the slideshow (persisted).
Ken Burns: default On, deliberately faint: scale 1.00 -> 1.05 and pan up to 1.5% of width, direction alternating per photo, linear over the whole interval (ease would make start/stop visible), applied in the Image's graphicsLayer lambda from an Animatable so nothing recomposes; the transform is updated at 30 Hz (every other frame) since the full-interval motion is sub-pixel per frame. The 5% upscale of a 1080p bitmap is invisible after the TV's own 1080p -> 4K scaler. Setting Ken Burns Off keeps the layer static (GPU idle between clock ticks).
Memory budget: GPU 2 x 8.3 MB hardware bitmaps during a crossfade (8.3 MB steady) + 2 x 0.5 MB thumb textures + clock offscreen layer ~1 MB; Java heap: thumbs 1 MB, icon cache ~1 MB (20 x 112^2 x 4), Compose ~40 MB; total process well under 150 MB PSS. Never decode a 4K image to a software bitmap (33 MB) and never hold more than two display bitmaps.
Cold start: persist lastWallpaperId; first frame draws the cached 480x270 thumb stretched full screen (instant, blurry) and crossfades to the full decode over 300 ms when it lands (~250 ms), so a Home press after Netflix never shows black. Empty folder: bundled 1920x1080 dark-gradient fallback plus a toast with the adb push command. Decode failure: skip, log, remove from the queue for this session.

## remoteUx

State machine: Ambient (row hidden) / Active (row visible, idle timer 10 s) / Overlay (All apps, Settings, Context menu, Wallpaper info). All keys enter one root Modifier.onPreviewKeyEvent KeyRouter so behaviour never depends on which node has focus. Long press = ACTION_DOWN with repeatCount 0 starts a 500 ms coroutine timer; firing marks the key handled and the following ACTION_UP is swallowed.
- D-pad Left/Right (21/22): Active: move dock focus; at either end a 6 dp bump (120 ms), no wrap. Ambient: wake only (consumed). Overlays: navigate; in Settings they cycle the focused row's value; in Move mode they swap the tile with its neighbour live (Modifier.animateItem 180 ms).
- D-pad Up (19): v1: bump; reserved for revealing rows above the dock in v2 (Home Assistant pills). Ambient: wake.
- D-pad Down (20): Active: open All apps (280 ms enter: alpha + 24 dp translate, CubicBezier(0.05,0.7,0.1,1)). Ambient: wake.
- OK / Select / Enter (23/66): Active: press animation 90 ms then launch via Intent(MAIN).addCategory(LEANBACK_LAUNCHER).setComponent(...).addFlags(NEW_TASK or RESET_TASK_IF_NEEDED); IntentTiles launch their parsed URI; ActionTiles run their action. Long OK (500 ms): tile context menu: Move, Hide, Set as Home focus, App info (Settings.ACTION_APPLICATION_DETAILS_SETTINGS). In All apps long OK offers Pin to dock / Unpin, Hide / Unhide, App info. Ambient: wake only.
- Back (4): closes the top-most overlay (context menu -> Move mode cancel restores the original order -> Settings -> All apps, exit 200 ms CubicBezier(0.3,0,0.8,0.15)); on the bare home screen with the row visible it hides the row immediately (Ambient); in Ambient it is a no-op. BackHandler always consumes, so the activity never finishes and never falls through to Amazon's home.
- Menu (82): toggles the Settings sheet from any state (also from Ambient, without the wake delay). Long Menu (500 ms): Wallpaper info card for 4 s (filename, WxH, index/total, next change in m:ss) for curating.
- Play/Pause (85): toggles the slideshow pause; toast "Slideshow paused" / "Slideshow playing" 1.5 s. Works in Ambient without waking the row.
- Rewind (89) / Fast-forward (90) and Media Previous/Next (88/87): previous / next wallpaper with the 1800 ms crossfade and a reset interval; toast "7/12 city-seattle-night" 1.5 s. Works in Ambient.
- Home: delivered by Home on Fire as a new HOME intent -> onNewIntent: close overlays, show the row, focus the Home-focus tile (default: first tile), refresh the app catalog. The activity is singleTask + stateNotNeeded + excludeFromRecents so this never recreates it.
- Volume, Mute, Alexa, Netflix/Prime/Luna buttons: untouched (Fire OS handles them).
Reaching settings: Menu, or an optional ActionTile(Settings) pinned to the dock. Settings sheet (Up/Down rows, Left/Right or OK change, Back closes): Wallpaper (Interval, Order, Ken Burns, Legibility scrim Auto/Off/On, Rescan folder), Clock (Style Glass/Solid, Hours Follow system/12/24, Show date, Position 43%/50%, Size S/M/L), Dock (Hide after idle, Labels Focused only/Always/Never, Show non-TV apps in All apps, Show hidden apps), Apps (every package with Pinned / Hidden toggles, the only place operator junk can be unhidden), Advanced (Export config to /sdcard/Download/glass-config.json, Import config, Keep screen awake Off, Version).
Hiding and reordering: long OK -> Hide shrinks the tile out in 160 ms and adds the component to config.hidden; hidden apps reappear in All apps' Hidden section when Show hidden is on, where long OK -> Unhide. Long OK -> Move enters Move mode (rim pulses white 0.6 <-> 1.0 at 900 ms), Left/Right swap live, OK commits (config saved), Back reverts. Pin/Unpin from All apps edits the dock row in config; the dock re-centres with animateItem.

## extensibility

Data model (kotlinx.serialization, class discriminator "type", ignoreUnknownKeys = true, encodeDefaults = true):
@Serializable sealed interface Tile { id: String; label: String?; icon: IconSpec? } with v1 subtypes AppTile("app": component "pkg/cls"), IntentTile("intent": intentUri from Intent.toUri(URI_INTENT_SCHEME), optional requirePackage so it hides when the target app is absent), ActionTile("action": AllApps | Settings | NextWallpaper | PauseSlideshow); v2 subtypes HaEntityTile("ha": entityId, kind Toggle | Scene | Sensor, optional serviceOverride), FolderTile("folder": children). IconSpec = AppIcon(component) | Vector(resName) | Emoji(text) | Monogram(letter, colour). TileRow(id, title?, style Dock | Pills | Cards, visibility Always | OnFocus | Hidden, tiles). LauncherConfig(schemaVersion = 1, rows, hidden: Set<String>, wallpaper: WallpaperConfig, clock: ClockConfig, dock: DockConfig, integrations: Map<String, JsonObject> for HA base URL/token etc.). Runtime state lives in a separate state.json (lastFocusedTileId, slideshowPaused, currentWallpaperId, shuffleSeed, queueIndex) so exports never carry volatile state.
Config store: files/config.json written atomically (temp + rename), loaded into a StateFlow<LauncherConfig>; Defaults.kt builds the default config from the installed catalog on first run; migrate(from: Int, json: JsonObject) runs chained per-version steps. Debug hooks: Settings -> Export/Import to /sdcard/Download/glass-config.json, and a debug-only BroadcastReceiver dev.sal.glass.RELOAD_CONFIG that re-reads that file, so Sal can edit the dock or HA entities on the Mac and `adb push` + `am broadcast` without a rebuild.
Registries (plain maps, no DI framework; one AppGraph object built in Application.onCreate): TileActionHandler<T : Tile> { suspend fun invoke(tile, ctx) } keyed by KClass; TileStateProvider { fun observe(tile): Flow<TileState> } (v1: AppInstalledProvider only; HA provider plugs in here); TileRenderer: a composable chooser by tile type, default renderer = GlassTile(icon, label, state) so any new type gets glass, focus lift and labels for free. TileResolver combines config + AppCatalog (PackageManager snapshot refreshed by PackageChangeReceiver) + providers into ResolvedTile(tile, icon ImageBitmap?, available Boolean, state TileState?) which is the only thing the UI renders.
Code structure, single :app module tonight, packages: ui.glass (GlassShape, Modifier.glass, GlassBackdrop + LocalGlassBackdrop, tokens), ui.home (HomeScreen, ClockBlock, Dock, LabelPill, Toast), ui.sheets (AllAppsSheet, SettingsSheet, ContextMenu, WallpaperInfo), wallpaper (WallpaperRepository, WallpaperDecoder, BlurThumb, WallpaperEngine state machine, pure Kotlin class with no Activity reference so a DreamService can host it later), apps (AppCatalog, IconCache, PackageChangeReceiver), tiles (Tile model, TileResolver, handler/provider/renderer registries), config (LauncherConfig, ConfigStore, Migrations, Defaults), input (KeyRouter, LongPressTracker), HomeViewModel exposing StateFlow<HomeUiState>(rows, focusedTileId, mode Ambient/Active/Overlay, wallpaper cur/next/progress, clock) plus an effects Channel (LaunchIntent, Toast). When HA lands, split :core-tiles and :feature-ha; the Tile interface and registries are already module-boundary shaped.

Dolphin is an AppTile.
Adding a Home Assistant toggle (about 200 lines): HaClient (OkHttp or ktor WebSocket to <ha>/api/websocket, long-lived token from config.integrations.ha, subscribe_entities), HaStateProvider mapping entity state -> TileState.On/Off/Unavailable, HaActionHandler posting /api/services/<domain>/toggle (or scene/turn_on), register both in AppGraph, ToggleTileRenderer (84x44 glass pill, on = accent 0.35 fill + rim x1.2, 150 ms state crossfade) selected for HaEntityTile; add a row {"id":"home","style":"pills","visibility":"OnFocus","tiles":[{"type":"ha","entityId":"light.living_room",...}]} that D-pad Up reveals above the dock. ## risks

- Hardware shadows on Path outlines: Outline.setPath (API 30) only casts shadows for convex paths and tessellates per frame; 9 casters is fine but a scaled squircle re-tessellates during focus springs. Mitigation: paths are convex rectangles with smoothing; measure with `adb shell dumpsys gfxinfo dev.sal.glass framestats` during a 10 s D-pad sweep (target: 0 frames > 16.7 ms, mean < 8 ms); a build flag swaps GlassShape to RoundedCornerShape(20.dp), which hits HWUI's round-rect fast path.
- Blur thumb upsampling looks blocky or shows bilinear diamonds on hard edges if under-blurred. Mitigation: 3-pass box blur radius 5 at 480x270 (sigma ~22 px at 1080p) before the 4x bilinear upsample; verify on city-hong-kong-harbour-night (point lights) and raise to radius 7 or 640x360 if needed; never sample the sharp bitmap.
- Glass numerals unreadable over busy bright regions (snow fields in aoraki-mount-cook, daytime skylines). Mitigation: zone-luma adaptive frost (white 0.60 -> black 0.28), 1.5 dp bright rim, 20 dp dark shadow, 110 dp cap height; Settings fallback Clock style Solid; threshold hysteresis (0.50/0.60) and per-wallpaper evaluation so it cannot flicker.
- Blurred text shadow on 152 sp glyphs costs a mask blur per draw if the clock layer re-renders every frame (Ken Burns runs continuously). Mitigation: clock in its own graphicsLayer with CompositingStrategy.Offscreen so it rasterises only on minute ticks and crossfades; fallback to two unblurred offset copies if gfxinfo shows > 1 ms attributable to the clock.
- Hardware bitmaps: a 8.3 MB AHardwareBuffer import can stall the render thread for one frame on MediaTek drivers, and hardware bitmaps cannot be read back or drawn to software canvases. Mitigation: decode with ALLOCATOR_HARDWARE on the IO thread, warm the texture with a 1-frame alpha 0.004 draw before the fade, keep all pixel work (blur, luma, accent) on the separate 480x270 software decode; never call readPixels on the display bitmap.
- Overdraw during the crossfade with Ken Burns: 2 full-screen 1080p textured quads + scrim + 9 panels ~3.2x overdraw = ~6.6 Mpix/frame, 400 Mpix/s at 60 Hz. Within Mali-G52 MP2 fill rate (> 2 Gpix/s) but it is the hot path; mitigation: the old image is drawn without alpha (opaque) so only one blended full-screen layer exists, Ken Burns transform updates at 30 Hz, and Ken Burns Off makes the screen fully static between minute ticks.
- Focus loss / focus traps: Compose TV focus is explicit, and alpha-hiding the dock, opening sheets, or reordering with animateItem can orphan focus, after which the D-pad does nothing. Mitigation: the dock stays composed in Ambient (alpha only), focusRestorer on the dock, every sheet requests focus in a LaunchedEffect on open and hands it back via a FocusRequester on close, and the root KeyRouter handles wake/Back/Menu/media keys regardless of focus, so the remote is never dead.
- Package visibility and junk: with targetSdk 36 the catalog is empty without QUERY_ALL_PACKAGES (declared), and com.mediatek.opapp alone contributes ~18 Leanback activities. Mitigation: QUERY_ALL_PACKAGES plus <queries> for MAIN/LEANBACK_LAUNCHER and MAIN/LAUNCHER, distinctBy package, default hidden list, and `adb shell dumpsys package queries` to confirm visibility after install.
- Icon quality: some TV apps ship only 48-72 px icons or an adaptive icon whose foreground is a tiny glyph, which looks soft or lost at 56 dp inside the tile. Mitigation: request DENSITY_XXHIGH (480) resources, composite adaptive icons at 112 px with the squircle mask, and fall back to a monogram tile when the best asset is < 96 px; log icon sizes on first catalog build so Sal can see offenders.
- Wallpaper scan lag: files pushed with adb are not in MediaStore until the media scanner runs, so new photos may not appear for minutes. Mitigation: directory listing fallback plus MediaScannerConnection.scanFile for unknown files on every Home press and rotation tick, and the Rescan folder action in Settings.
- Cold starts after Fire OS kills the launcher behind Netflix would show black for 300-700 ms. Mitigation: windowDisablePreview + black window background (already in Theme.Glass), first frame from the cached 480x270 thumb crossfading to the full decode, R8 minification on, and no DI/reflection; measure with `adb shell am start -W` (target < 600 ms to first frame).
- Idle-hiding the row could confuse guests who see only a photo and a clock. Mitigation: any key wakes the row in 220 ms with the last-focused tile lifted, Back-to-hide is symmetrical, and the idle delay is a setting (Never disables it).
- Memory on a 192 MB heap / 32-bit process: an accidental full-4K software decode (33 MB) or a leaked previous bitmap would push the heap limit. Mitigation: setTargetSize always, hardware allocation for display bitmaps (off-heap), explicit recycle after each crossfade, a two-bitmap invariant asserted in debug builds, and a StrictMode/leak check of WallpaperEngine in debug.
- Inter variable-font axes or tnum might not apply through Compose on this OEM Skia build. Mitigation: ship static Inter files (InterDisplay-Medium, Inter-Medium, Inter-SemiBold) instead of the variable font, verify tnum by watching 11:11 -> 12:12 width on device, and fall back to monospaced digit slots (fixed-width Box per glyph) if widths still shift.
